# 汉化补丁发布

## 选择发布模式

- **简化版上传**沿用玩家发布流程，交付玩家说明、演示截图、补丁和校验值。用户只要求上传 GitHub、未指定模式时，采用简化版。按玩家交付范围准备提交。
- **开发版上传**同时交付同样的玩家内容和可复建的开发工程。按 [开发工程交接](developer-handoff.md) 从干净环境完成无 AI 构建、安装和恢复验证，再提交开发文件。验收受阻时报告具体问题，保留用户选择的发布模式。
- 两种模式都在用户明确要求上传对应项目后执行。由简化版追加公开开发资料属于开发版上传，采用用户确认的范围。玩家下载入口可继续使用同一仓库。

## 交付检查

- 使用最终构建生成的独立安装 ZIP 和对应的 SHA-256 校验文件。核对包内使用说明、适配游戏版本、安装和恢复入口、许可证及允许再分发的内容。
- 核对隔离环境中从最终 ZIP 解压后的安装、状态检查和恢复结果，按项目承诺范围验证升级。
- README 与 Release 说明包含实际适配版本、下载入口、安装与恢复步骤、变更内容、实测范围及四条版权与免责声明。区分已观察的实机场景、静态检查和未测试内容。包内的使用说明也附同一声明及实际分发组件的许可证。
- GitHub 仓库 README 展示 3～5 张实机演示截图，优先采用用户提供的图并保留其内容。缺少合适截图时，用隔离测试副本采集。

## GitHub Release

- 用户明确要求把该汉化项目上传到 GitHub 后，使用已确认的目标仓库、版本与发布范围。创建对应版本的 GitHub Release，把可安装的汉化 ZIP 和 SHA-256 校验文件上传为 Release 附件。候选测试版标记为 Pre-release。
- 发布后打开 Release 和 README 检查链接和图片。公开 Release 从玩家下载路径下载 ZIP，复核字节哈希与校验文件一致。私有 Release 按其访问权限验证。若附件或 Release 发布受阻，说明实际完成情况与阻碍。
- 仓库提交、Release 创建和附件验证分别记录实际结果。保护已有发布产物，发布新版本时使用对应的新版本号。
