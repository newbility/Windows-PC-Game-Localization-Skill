# 开发工程交接

用户选择开发版上传时，保留 [玩家发布交付](github-release.md)，再准备一份按文档即可维护和复建的开发工程。现有项目可先在隔离目录整理及验证。

## 可编辑的构建输入

- 公开构建读取的当前译文、稳定 ID、术语和必要的字段映射、排字配置等制作数据。同一范围约定一个当前译文入口。历史批次可用于溯源和 AI 续跑。普通编辑器可以完成一条人工修订，通过脚本重新生成输入校验，沿用原文哈希、变量、控制码和字形检查。
- 提供可执行的提取、校验、回填、构建脚本及安装器源码。构建以接手者提供的原版和公开可获取的依赖为输入。旧版候选、提取结果和诊断报告若是构建所需，追到原始输入并在本次流程生成。保留当前版本已有的代码、渲染和布局修复。
- 记录平台、目标游戏版本及构建读取的关键原版文件的相对路径与哈希。游戏安装目录放在被忽略的项目本地配置，项目内路径相对于项目根目录定位。说明版本不匹配时如何识别受支持的版本。
- 提供项目自己的锁文件和已验证的 [依赖准备入口](toolkit.md)。记录依赖公开来源、版本、校验值和许可证。宿主依赖给出官方安装方式及项目验证规则。只允许通过校验的依赖参与构建。
- 从本地原版提取可重建的原文和图像。仓库保存重建所需的译文、脚本和获准再分发的素材。较大的必要制作素材可以另作校验过的开发附件。用明确的文件清单审查拟公开内容，排除商业游戏本体、无再分发许可的资源、个人路径及存档、测试游戏副本、解包缓存、历史构建和凭据。给开发资料和第三方组件附适用的许可说明。

## 面向接手者的说明

在 README 指向开发说明，例如 `CONTRIBUTING.md`。使用项目实际验证过的命令和路径，解释如何准备游戏和依赖、找到并修改当前译文、重新校验、生成安装包，以及在隔离副本中安装和恢复。记录当前进度、已知问题和可从本地原版重建的大文件。构建和维护流程从普通终端运行，所需输入随项目和依赖准备过程取得。

## 开发版验收

1. 在本轮专用的 [临时验收目录](#临时目录与自动清理) 准备干净的工程副本和隔离的目标平台环境，使用对应版本原版游戏。依赖按公开说明获取或导入，环境里没有原项目的工具缓存、历史构建、聊天记录或 AI 服务。
2. 先构建当前译文，核对已发布基线涉及的内容和功能。再用普通编辑器修改一条可见译文，从清洁输出目录执行校验、回填及打包。图中文字等独立构建路径参与当前交付时，也要验证它们能按说明重建。
3. 从新生成的最终包安装到隔离副本，观察修订，并执行恢复后核对原版文件。需启动游戏时先隔离存档、配置和云同步。
4. 记录原版输入和依赖版本、成功的步骤、产物及其校验值，注明实际观察范围。以安装、恢复和内容验证为交接通过条件。逐字节复现既有 ZIP 可作为有明确要求时的单独目标。

随后按 [GitHub 发布](github-release.md) 检查待提交清单，验证仓库里的开发入口和玩家 Release 下载路径。

## 临时目录与自动清理

此步骤仅适用于开发版。Codex 在已有的工作区临时目录下运行 [HandoffWorkspace.ps1](../scripts/HandoffWorkspace.ps1) 创建本轮目录，记录返回的 `RunId` 和 `Workspace`。把候选提交的独立检出或导出、测试用译文、临时构建和本轮专用的游戏测试副本放在该目录的子目录内。检出和游戏副本使用独立文件。原项目、工具库、正式游戏和已有测试副本留在该目录外。

开发版验收通过后，将正式安装包、校验文件和验收记录保存到临时目录外，并核对这些文件可用。本次 GitHub 上传或发布后验证还要读取临时目录时，保留到最后一次使用完成。等构建、游戏及安装器进程都退出后，Codex 从临时目录外运行清理入口。

```powershell
# 从技能根目录调用。scratchRoot 是当前工作区内已存在的临时目录。
$handoff = & ./scripts/HandoffWorkspace.ps1 create -ScratchRoot $scratchRoot
# 在 $handoff.Workspace 内完成验收，并在目录外保存正式产物和记录。
# 验收通过且临时文件已使用完毕后，才调用清理。
& ./scripts/HandoffWorkspace.ps1 cleanup -ScratchRoot $scratchRoot -RunId $handoff.RunId -Completed
```

验收失败、任务中断或仍需临时文件时，保留临时目录并记录路径。清理入口按本轮编号、目录范围和标记文件验证目标，遇到目录链接或其他校验错误时停止，报告路径和失败原因。清理范围只包含本次登记的目录。
