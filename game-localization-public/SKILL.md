# 游戏简体中文汉化

按当前任务选择开工、续跑、排版修复、打包或发布。先读取当前项目的 `AGENTS.md`、使用说明和已有进度，复用已确认的参数、译文和构建流程。

用户明确要求上传汉化项目到 GitHub 时，按 [GitHub 发布](references/github-release.md) 执行。指定开发版上传时，还要完成 [开发工程交接](references/developer-handoff.md)。指定简化版或仅要求上传 GitHub 时，沿用玩家发布流程。

## 开工前检索已有汉化

新项目在确认游戏名称、发行平台和必要的只读版本信息后，先联网检索是否已有可用汉化，再开始资源提取、测试环境搭建、翻译或构建。此步骤不能只凭已有知识判断，也不能拖到翻译完成后补做。

- 用游戏英文名及已知中文名组合“汉化”“中文补丁”等关键词搜索；优先核对作者/汉化组原帖、发布页或仓库，辅以Steam社区和相关玩家社区。顺带核对目标版本是否已提供官方中文。区分同名游戏、重制版、不同平台及不同发行版本，不把其他版本的补丁直接视为适配。
- 在项目reports/existing-localizations.md或等效记录中保存检索日期、来源链接、作者/团队、补丁版本与更新时间、简体/繁体、适配平台/游戏版本、作者声称的覆盖程度、下载是否仍可访问，以及尚未验证的事项。搜索摘要和转载不能证明兼容或可用；未下载/运行时明确写“未实测”。不自动下载、执行或安装现成补丁。
- 查到已有完整或部分汉化补丁时，先向用户展示有来源链接的简明结果和已知适配限制，再请用户决定是否继续自行汉化、停止该项目，或另行研究现成补丁。决定到达前暂停依赖该决定的汉化准备、翻译与构建。用户选择继续后，将决定记入项目约定并恢复工作；现成补丁的存在不代表其译文、字体或程序允许复用。
- 没找到时只写“在本次检索范围内未找到可核实的现成汉化补丁”，记录搜索范围后继续已授权工作，不能断言一定不存在。只有预告、失效下载或疑似结果时，如实说明证据和可用性限制，交给用户判断；网络不可用时说明检索未完成，不冒充已查无结果，也不自行绕过此前置检查。
- 常规续跑复用已有检索记录和用户决定，不每轮重复搜索或重复询问。用户要求重新检索，或游戏平台/版本发生影响适配的变化时再更新。

## 开工参数

先从用户消息和项目文件查明以下信息。只集中询问会影响当前工作的缺项，说明无语音的项目可记为「无」。能独立进行的只读检查可先做。

- 游戏名称、正式游戏目录、目标发行平台及版本。能从安装文件确认的版本直接记录。
- 翻译依据的原版文本语言和语音语言，分别记录。
- 初译模型名称和推理强度、校对模型名称和推理强度、计划采用的简体中文字体。
- 已有术语库、前作官中、重制版中文或其他参考译文。记录来源和适用范围，用于保持专名与固定术语的一致性，并按本作语境处理差异。
- 到发布阶段再补齐仓库、发布版本、译文协议、字体和其他组件的许可证。复用已有确认记录。

把本项目的参数和开发约定整理进项目 `AGENTS.md`。使用说明记录项目目录、构建和测试入口，以及玩家所需的安装、校验和恢复步骤。公开说明使用可移植路径，开发机目录只留在内部文档。

## 工具与测试隔离

- 按 [共享工具库与项目配置](references/toolkit.md) 定位或初始化本机工具库。已有项目用已验证的入口和版本；采用公开工具链的新项目和交接项目使用同一套配置、依赖准备及校验入口。项目锁记录所需版本、来源、许可证、相对路径和 SHA-256。复用通过校验的组件，按项目补齐缺项，保护其他项目已锁定的版本。
- 解包资源、译文、游戏专用脚本、构建产物、日志和截图保留在项目内。正式安装、原存档、正式配置和云同步数据保持只读。默认在本机运行项目内的 `test-game` 副本，按 [实机抽检与配额](references/gameplay-sampling.md#启动本机测试副本) 做最小必要隔离和前后复核。
- 在批量应用译文前执行 [汉化排版预检](references/layout-qa.md)。用计划发布的字体和实际渲染路径做样包。修复排版或准备最终打包时，按同一参考做回归。

## 内容覆盖判定

开工时按 [汉化内容覆盖判定](references/content-coverage.md) 盘点文本、图中文字、播片和语音。记录本作所需的回填方式及待查范围，在批量应用前验证实际采用的各类显示方式。

## 分批翻译、校对与续跑

- 已有字幕的内容以已指定的原版字幕文本为依据进行翻译和校对，沿用原字幕入口及可复用的时序，无需额外核听、转录或处理配音。仅对有语音但没有字幕的内容，按内容覆盖判定进行语音核查、转录、听校及中文字幕补充，并记录实际听取的内容。保持语义、语气、剧情氛围和角色表达风格，保留变量、格式标记、控制码和分支语义。
- 初译使用用户指定模型及推理强度的子代理按批次并行执行。校对使用用户指定模型及推理强度的子代理复核冻结输入。指定模型、档位或子代理能力不可用时，先说明并暂停受影响步骤，等待用户指定处理方式。并发不足时排队。
- 为原文保留稳定 ID、来源和原文哈希。初稿、冻结校对输入、校对稿和检查报告分别保存。记录批次和分段检查点，完整校验后再合并。恢复时检查已有记录并只续未完成 ID。保留已完成成果，修订另建版本。
- 检查漏译、重复或缺失 ID、原文哈希漂移、变量及控制标记、字体字形覆盖。单独记录语义校对、静态检查和实机已观察场景，明确未测剧情、分支及分辨率。

## 有上限的实机抽检

本机副本隔离核实后，先验证能直接进入的代表性显示路径。剧情和分支按 [实机抽检与配额](references/gameplay-sampling.md) 判断可行性并限定规模。中后段入口不可达时，保留主菜单、设置和开场等实测结果，记录未覆盖范围。无法启动时继续静态和安装验证。不为凑配额从头游玩或开发复杂跳转工具。用户已有范围、上限和停止要求优先，续跑沿用原计数。

## 打包交付

- Windows 默认交付独立图形安装包。界面支持浏览选择以及手动输入或粘贴游戏目录，并提供安装、检查状态和恢复原版。图形与命令行入口复用同一安装逻辑（如同时提供两种入口）。
- 在隔离目录中从最终压缩包解包，验证两种目录输入、安装、检查状态及恢复。核对安装和恢复后的文件，按已承诺的适配范围验证升级。
- 补丁附使用说明、必要的运行组件及允许再分发的许可证，独立于共享工具库。优先分发差分及获准再分发的资源。需要公开交付时使用 [发布说明和版权模板](references/github-release.md)，并以实测结果填写覆盖范围。
